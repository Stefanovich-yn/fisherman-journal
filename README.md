# Fisherman's Journal (Журнал рыболова)

Консольное Java-приложение с многослойной архитектурой для учета и фиксации уловов рыболовов-любителей или членов рыболовного клуба.

---

## 1. Предметная область

Приложение позволяет регистрировать записи об уловах, отслеживать их жизненный цикл через статусы, искать данные по различным критериям и рассчитывать агрегированную статистику.

### Сущность `CatchRecord`:
* `id` — уникальный числовой идентификатор (назначается автоматически).
* `fishermanName` — имя рыбака (не пустое).
* `fishType` — вид пойманной рыбы (не пустое).
* `quantity` — количество пойманных единиц рыбы данного вида (от 1 до 100 шт.).
* `weight` — общий вес улова в граммах (от 100 до 30 000 г).
* `waterBody` — наименование водоема (от 3 до 50 символов).
* `status` — статус записи (`RecordStatus`). Новая запись всегда получает статус `NEW`.
* `createdAt` — дата и время создания записи (назначается автоматически).

### Жизненный цикл статусов (`RecordStatus`):
* `NEW` $\rightarrow$ `VERIFIED` или `CANCELLED`
* `VERIFIED` $\rightarrow$ `REGISTERED` или `CANCELLED`
* `REGISTERED` $\rightarrow$ `ARCHIVED`
* `ARCHIVED` и `CANCELLED` — финальные статусы (дальнейшее изменение запрещено).

## 2. Архитектура приложения

Приложение построено в строгом соответствии с принципами многослойной архитектуры (**Layered Architecture**):

`Main → Controller → Commands → Logic (Service) → DAO → catch_records.txt`

Слои слабо связаны между собой и обращаются только к интерфейсам нижележащих уровней через централизованные синглтон-провайдеры (**Singleton-providers**):

* **`entity`** — модели предметной области (`CatchRecord`, `RecordStatus`).
* **`dao` / `dao.impl`** — слой доступа к данным (`RecordDao`, `FileRecordDao`, `DaoProvider`). Отвечает исключительно за чтение, запись, обновление файла и потокобезопасную генерацию ID. Оборачивает `IOException` в `DaoException`.
* **`logic` / `logic.impl`** — слой бизнес-логики (`RecordLogic`, `RecordServiceImpl`, `LogicProvider`). Отвечает за валидацию данных, проверку разрешенных переходов статусов, фильтрацию и расчет статистики с помощью **Java Stream API**. Оборачивает `DaoException` в `LogicException`.
* **`controller` / `controller.impl`** — слой контроллера и команд (`Controller`, `Command`, `CommandName`, `CommandProvider`). Реализует паттерн «Команда». Извлекает имя команды, разбирает текстовые параметры запроса, перехватывает ошибки и формирует понятные строковые ответы для пользователя.
* **`main`** — точка входа (`Main`), содержащая сквозные демонстрационные сценарии.

## 3. Формат хранения данных

Данные сохраняются в текстовом файле **`catch_records.txt`** в корневой папке проекта.

* Каждый улов хранится строго на одной строке.
* В качестве разделителя полей используется символ точки с запятой (`;`).
* Порядок следования полей:
  `id;fishermanName;fishType;quantity;weight;waterBody;status;createdAt`

**Пример строки в файле:**
```text
1;Ivan Petrovich;Pike;3;4500;Volga River;NEW;2026-09-07T09:34:23.894857
```

4. Список поддерживаемых команд

    CREATE_RECORD — создать новую запись об улове.

    CHANGE_STATUS — изменить статус существующей записи.

    FIND_BY_FISHERMAN — найти записи по имени рыбака (частичное совпадение, без учета регистра).

    FIND_BY_FISH — найти записи по виду рыбы (частичное совпадение, без учета регистра).

    FIND_BY_WATERBODY — найти записи по названию водоема (частичное совпадение, без учета регистра).

    GET_STATS — получить агрегированную статистику по конкретному рыбаку.

    SHOW_ACTIVE — показать все незавершенные записи (статус не ARCHIVED и не CANCELLED).

    SHOW_ALL — показать абсолютно все записи журнала.

5. Примеры текстовых запросов

Каждый запрос состоит из имени команды на первой строке и параметров в формате key=value на последующих строках.

CREATE_RECORD
fisherman=Ivan Petrovich
fish=Pike
quantity=3
weight=6000
waterBody=Neman River

CHANGE_STATUS
id=1
status=VERIFIED

FIND_BY_WATERBODY
waterBody=neman

GET_STATS
fisherman=Ivan Petrovich

6. Инструкция по запуску
Требования:

    Установленный JDK 25 (или JDK 17+).
    Среда разработки: IntelliJ IDEA или Eclipse.
    Внешние библиотеки и фреймворки не требуются (чистый Java SE).

Запуск через IDE:

    Клонируйте репозиторий или импортируйте проект в среду разработки как существующий Java-проект.
    Убедитесь, что в свойствах проекта (Project Structure / Build Path) выбран JDK версии 25.
    Откройте класс com.steff.fishermanjournal.main.Main.
    Запустите метод main() (нажмите сочетание Ctrl + Shift + F10 в IntelliJ IDEA или кликните правой кнопкой мыши → Run As → Java Application в Eclipse).
    Результаты выполнения цепочки сценариев отобразятся во встроенной консоли IDE.
